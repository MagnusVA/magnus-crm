### Header and global controls

`WorkspaceShellFrame` owns SidebarProvider and a skip-to-content link before Suspense. `WorkspaceShellClient` owns Sidebar/SidebarInset, a 48px header, sidebar trigger, separator, breadcrumbs, then CommandPaletteTrigger, ThemeToggle and NotificationCenter. Main content uses `p-6` and scrolls independently. Operations opens automatically when inside its section. Cmd+1 through Cmd+4 navigate the current top-level nav array.

`components/workspace-breadcrumbs.tsx` uses `hooks/use-breadcrumbs.ts`. Workspace and closer home omit crumbs; closer paths omit the workspace prefix. Unmapped segments, including several static segments as well as IDs, appear as `...`. The component supports overrides, but the shared shell supplies none. Breadcrumb ancestor links can point to compatibility redirects.

`components/command-palette.tsx` has its own menu, not the sidebar config. Cmd/Ctrl+K opens it. Admin order: Overview, Operations, optional Billing, Leads & Customers, Lead Gen Ops, Lead Gen Settings, Respark, Team, Settings, Attribution. Closer order: Dashboard, My Pipeline, Leads & Customers, My Schedule, which aliases Dashboard. Lead generator order: Capture, My Activity, Respark. Quick actions link admins to Team for Invite team member and O/A/C to New Side Deal, labeled Create opportunity. Reports and Profile are absent from the palette. Its shortcut labels can diverge from the shell array when Billing is enabled.

`components/notification-center.tsx` is a bell/popover with unread badge and empty state, backed by a literal empty array and a TODO for a query. It currently has no live notifications. `components/theme-toggle.tsx` switches themes through next-themes. Calendly/Slack connection guards sit in `app/ConvexClientProvider.tsx`, outside the page shell.

## 4. Shared patterns and divergences

### Page structure and headers

Most server pages are thin guards around a client; reports inherit their guard from their layout. Lists and operational dashboards often use server Suspense with a route-specific skeleton. Details preload authenticated Convex queries. `app/workspace/leads-customers/[leadId]/_components/entity-detail-content.tsx` is an extra async bridge around that preload.

There is no common page-header component across these screens. `app/workspace/closer/pipeline/_components/closer-pipeline-page-client.tsx`, `app/workspace/team/_components/team-page-client.tsx`, and `app/workspace/settings/_components/settings-page-client.tsx` use local headings, commonly `text-3xl font-bold`. `app/workspace/leads-customers/_components/entity-browser-toolbar.tsx` uses `text-2xl font-semibold`, integrated search and New Side Deal. `app/workspace/lead-gen/_components/lead-gen-respark-page-client.tsx` uses `text-2xl font-semibold tracking-normal`; attribution uses a compact title with back link. The person detail frame adds its own `px-4 sm:px-6 lg:px-8` inside the shell padding and has a maximum width and sticky aside. Meeting/reminder details instead compose cards and action bars.

### Tables, cards, charts and pagination

Tables use `components/ui/table.tsx`, with different local wrappers rather than one universal data-table interface. The live closer pipeline reuses `app/workspace/_components/pipeline/opportunities-table.tsx` with load-more pagination. Person search has custom `entity-result-row.tsx` and `entity-result-mobile-card.tsx`; it deliberately switches from desktop table to cards below `md`. Billing has `billing-queue-table.tsx`; Team has `team-members-table.tsx`; booking reviews render a local table directly. Lead gen has specialist, respark, conversion, origins, and raw-submission tables.

Operational dashboards use `app/workspace/_components/goal-progress-ring.tsx` and `ops-bar-chart-card.tsx`, often alongside contribution tables and detail lists. Report clients compose separate report-specific KPI cards, charts, tables and feed components under `app/workspace/reports/*/_components`. `app/workspace/_components/analytics/analytics-freshness.tsx` supplies the freshness line, and `analytics/use-analytics-report.ts` supplies report loading/data. Export/report jobs use `app/workspace/operations/_components/operations-report-export-menu.tsx`, `report-job-status.tsx` and `use-operations-report-job.ts`. These states must remain visible in the redesigned dashboard archetype.

### Forms, sheets and dialogs

New Side Deal uses `app/workspace/opportunities/new/_components/create-opportunity-page-client.tsx` and `create-opportunity-schema.ts` with React Hook Form, Zod and standardSchemaResolver; field primitives come from `components/ui/form.tsx` and `field.tsx`. Capture uses an origin/session flow before identifier input. Lead gen settings and billing use simpler local fields. Team actions are lazy dialogs, redistribution is a full-page wizard, and merging remains a full-page search/preview/confirmation flow.

Canonical deal details are a sheet within person details: `app/workspace/leads-customers/[leadId]/_components/opportunity-detail-sheet.tsx`, `opportunity-sheet-context.tsx`, `opportunity-sheet-body.tsx`. Selection can be deep linked with `?opportunityId=`. The sheet reuses components physically under the legacy `app/workspace/opportunities/[opportunityId]/_components/` folder. Those components remain live even though their page redirects. Respark has a separate restricted `app/workspace/lead-gen/_components/respark-person-sheet.tsx`; it must preserve masked phone/email and held-batch scope.

### Empty, loading, unavailable and error states

`components/ui/empty.tsx` is the main composable empty primitive. Person browser has search-specific versus no-data messages in `entity-browser-results.tsx`; one message mentions projection backfill. Closer screens also use `app/workspace/closer/_components/closer-empty-state.tsx`. Notifications use a plain text empty popover. Billing has a distinct `app/workspace/billing/_components/billing-unavailable.tsx` for feature availability. Details often have inline not-found/empty states, whereas legacy person/deal resolvers call notFound on expected invalid/inaccessible IDs.

Loading is layered. `app/workspace/loading.tsx` and `workspace-shell-skeleton.tsx` cover workspace entry/auth; many route `loading.tsx` files wrap named `*-skeleton.tsx` components. Reports share `app/workspace/reports/loading.tsx`, with additional route loading files only for reminders and Slack qualifications; individual report clients also own report-specific skeletons. `closer/pipeline/_components/closer-pipeline-page-client.tsx` defines its header/table skeletons inline. Canonical person detail has `entity-detail-skeleton.tsx`, plus `opportunity-sheet-skeleton.tsx` for nested deal loading. Not every page has its own loading file, despite the frontend guide generalization.

Errors use `app/error.tsx`, `app/global-error.tsx`, and `app/workspace/error.tsx`; the legacy closer reminder detail additionally has its own `error.tsx`. Workspace/root boundaries show retry and an error digest and report errors. `app/workspace/_components/section-error-boundary.tsx` handles independently failing client sections, such as Settings tabs, Respark summaries and the deal sheet; its default fallback is an inline alert without a retry action. Onboarding and DM portal handle domain failures as local card/alert states.

## 6. Open questions

1. What is the intended current entry point for `/workspace/pipeline/reminders/[followUpId]`? Repository search found no live list link to the admin route. The only direct legacy reminder links found are in the closer dashboard, which admins cannot open. A real tenant reminder ID would need read-only data access or a retained external link to verify this screen at runtime.
2. Should merge and redistribution receive explicit page-level permission guards during implementation? They currently inherit workspace access. Merge queries/mutation admit O/A/C; redistribution client and query admit O/A. This audit records the gap and does not change authorization.
3. Are the remaining legacy reminder routes still needed by production data? The closer dashboard distinguishes stale_opportunity_nudge entries from other reminders, but a source audit cannot count live records.
4. Which visual states exist in the live test tenant? No valid production IDs, portal passwords, onboarding tokens, or billing enablement were retrieved. Entry-point sources are mapped, but runtime rendering, responsive appearance and actual record availability remain unverified.
5. Should the command palette and sidebar share a navigation model? They currently differ in destinations and admin shortcut labels, and reports are missing from the palette. The notification center also needs a product decision about remaining a placeholder.
6. Are lost legacy query filters intentional? Pipeline forwards filter query strings to opportunities, whose index then redirects without forwarding them; old leads forwards only converted. These behaviors are explicit in code, but intent is not documented.
7. `PRODUCT.md` and `DESIGN.md` are absent according to impeccable context. Product/visual direction belongs to the parent redesign task; this research creates neither file.
